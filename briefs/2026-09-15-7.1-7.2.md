## Goal

Цитата плана §4 / «Ближайшие шаги» п.1: виды `trace.rag` и `trace.llm`; у каждого `orchestrator.decision` в payload всегда `llm` (токены, `finish_reason`) и `rag` (запрос, статус, id карточек); `orchestrator.resume` через `execRef()` и в `EVENT_KINDS`; Attach оркестратора и агентов пишет `trace.rag`; лог («Режим разработчика») и `mas_trace_case.py` показывают запрос в базу, карточки, токены и `finish_reason`. Чат инженера этих строк не видит.

Зачем: сейчас лог слепой на том, что видела модель и что нашла база. Пока этого нет, правки RAG/промпта/thinking недоказуемы. После этого брифы 7.3 и 8.1 опираются на воспроизводимый лог, а не на ручной разбор executions n8n.

Критерий сессии: любой live-кейс (хотя бы один commissioning из `--live`) в `GET /cases/{id}/log` содержит `trace.rag` с `query`/`status`/`cards[].knowledge_id` и у каждого `orchestrator.decision` — `payload.llm.finish_reason` и токены в заголовке («N tok»). Пустой срез Builder (`status=unavailable`, `SCHEMA_KEYWORD_SCOPE_REQUIRED`) — ожидаемый факт, не провал этого брифа.

## Contracts to respect

Поле: n8n 2.30.8 только UI; сервисы — `.venv` + `requirements.txt`; БД только через Control Plane Proxy; адреса — Runtime Config; секретов в JSON нет. Лабораторный Docker/REST не делать единственным путём фичи.

События: лента = источник истины; `trace.*` только лог (`is_trace_kind`). Человеку — русская проза без snake_case/JSON; в title лога идентификаторы можно. Большие поля — `boundedForLog` / `compact_for_log`. Ссылка на execution только если в payload есть `execution_id` и `workflow_id` (`execRef()` в JS, `exec_ref_js` у агентов).

Новые payload (план §4 7.1):

```
trace.rag:  {caller, query, filters, status, findings:[{code}], cards:[{knowledge_id, revision, rrf_score, branches}], duration_ms}
trace.llm:  {role: decision|verify|interpret, model, prompt_tokens, completion_tokens, finish_reason, duration_ms,
             tool_calls?, prompt_preview ≤4K, content_preview ≤2K}
orchestrator.decision.payload.llm  — как trace.llm без prompt/content
orchestrator.decision.payload.rag  — компакт: query, status, cards[{knowledge_id, rrf_score, branches}]
orchestrator.resume.payload        — {source, task_id, ...execRef()}
```

Ключ `error` в ответе инструмента по-прежнему запрещён; к событиям лога это не относится.

Узлы: не `toolHttpRequest`; Code без `require`/`$env`; HTTP Request 4.4 как у `agent.accepted`. После шаблона — реген.

Двойники: kind в kit и Activity согласованы; JS inlined `mas_state_utils` идентичен во всех Code оркестратора (smoke).

Live α2 не ослаблять: `mismatch_count: 0`, `warnings: 0`, `steps ≤ 6`, `tool_calls ≤ 4`, без повторных HITL и `completion_review`. Пустой RAG Builder не считать warning этого брифа.
