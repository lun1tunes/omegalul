Ошибка в ноде `Finalize indexes and deduplicate chunks` означает, что в подключенной PostgreSQL-базе нет таблицы `tnavigator_schedule_knowledge_v1`.

Что сделать через n8n UI:

1. Открой workflow `MAS — Knowledge Ingestion`.
2. Открой ноду `Ensure parent knowledge tables` и в начало SQL добавь:

```sql
CREATE EXTENSION IF NOT EXISTS vector;
CREATE EXTENSION IF NOT EXISTS pgcrypto;

CREATE TABLE IF NOT EXISTS tnavigator_schedule_knowledge_v1 (
  id uuid PRIMARY KEY DEFAULT gen_random_uuid(),
  text text NOT NULL,
  metadata jsonb NOT NULL DEFAULT '{}'::jsonb,
  embedding vector(1536) NOT NULL
);
```

Остальной SQL в этой ноде оставь без изменений.

3. Проверь, что один и тот же PostgreSQL credential выбран в нодах:
   - `Ensure parent knowledge tables`
   - `PGVector — insert approved SCHEDULE knowledge`
   - `Finalize indexes and deduplicate chunks`
4. Проверь, что credential подключается к той же базе и схеме. Если используется не `public`, укажи схему явно или добавь `SET search_path` в SQL.
5. Запусти workflow целиком заново.

Размерность `vector(1536)` соответствует используемой модели `text-embedding-3-small`. Если embedding-модель другая, размерность должна совпадать с ней.

Если n8n покажет ошибку на `CREATE EXTENSION` или не позволит создать таблицу, в корпоративном контуре нужны права DBA. Тогда администратор PostgreSQL должен выполнить этот SQL в той же базе, к которой подключен credential n8n.

Для контекста:
- workflow инжекта знаний: `MAS — Knowledge Ingestion`;
- нода, которая вставляет знания: `PGVector — insert approved SCHEDULE knowledge`;
- нода с проблемой: `Finalize indexes and deduplicate chunks`.
